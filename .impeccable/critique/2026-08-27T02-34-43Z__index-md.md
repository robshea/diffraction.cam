## Design Specificity Verdict

**LLM assessment**: Not a reskinned generic calculator — built around one specific physical relationship. The UV/Visible/IR band structure mapped to real nanometer values, the pixel-pitch readout that changes per camera, and the filter dropdown that dims exactly the columns a physical filter would block are the product, not decoration. DESIGN.md's "Field Instrument" concept is genuinely realized: no display typeface, no shadows, no drama — all custom effort goes into the color-coded data. The one place specificity thins is the shared minimal-mistakes theme chrome, which is appropriate per DESIGN.md's own instruction.

**Deterministic scan**: Ran in degraded regex-fallback mode (missing htmlparser2/css-select/css-tree/domutils). Its one finding ("11 em-dashes" on /thirds/) was confirmed a false positive — `--` inside HTML comments and BEM class names like `btn--success`, misread by the fallback. Treat the scan as inconclusive, not a clean bill of health.

**Visual overlays**: In-page injection failed — mixed content block (HTTPS site, HTTP local helper), confirmed via a hung/timed-out fetch. No user-visible overlay produced. Assessment B's direct visual observation at ~1430px showed no defects and no console errors; separately, reading the CSS source directly found the diffraction table has no overflow-x wrapper unlike the Cameras table — independently corroborating Assessment A's live-measured finding on the calculator's missing mobile treatment.

## Overall Impression

The core interaction is well-composed, on-brand, and fast for the common case, genuinely executing the "Field Instrument" intent. But it has no guard rails: every edge case reached (no camera selected, a stale bookmarked URL, a filter that dims a column) failed silently or alarmingly rather than gracefully — direct hits against PRODUCT.md's own principles of visible reasoning and shareable results.

## What's Working

1. **Row-selection highlight.** Immediate 2px navy border on click, no reload — the tool's one moment of commitment, handled with exactly the restraint DESIGN.md calls for.
2. **URL-persisted calculator state.** Camera/filter write straight to history.replaceState; the thirds/whole toggle carries selection forward — the static architecture serving a real product principle.
3. **The Cameras page filter panel.** Live search, sortable columns with aria-sort, aria-live results count, real mobile breakpoint — the most fully accessible, fully realized interaction on the site.

## Priority Issues

**[P0] Clearing or invalidating the camera selection breaks the table with no explanation**
- Why it matters: Confirmed live — clearing the camera fills ~110 cells with "Infinity" in solid red; a stale/mistyped `?camera=` URL throws mid-script leaving the table blank. Both directly undermine PRODUCT.md's shareable/bookmarkable-results principle.
- Fix: Short-circuit calculation on empty/NaN pitch with an inviting empty state; guard the camera-lookup `.find()` against a non-matching URL param.
- Suggested command: /impeccable harden

**[P0] Dimmed (filtered-out) columns drop to ~1.3:1 text contrast — effectively erased**
- Why it matters: Measured — flat `opacity:.25` takes "good" from 5.20:1 to 1.35:1, "maybe" 4.08→1.31, "bad" 4.48→1.30, on nearly every filter choice, for every user.
- Fix: Dim via background saturation/lightness reduction rather than flat opacity, or floor opacity above the contrast-collapse point.
- Suggested command: /impeccable audit

**[P1] Locked "maybe"/"bad" rating colors fail WCAG AA even at full opacity**
- Why it matters: Measured 4.08:1 and 4.48:1, both below the 4.5:1 floor, on the two states users most need to read correctly.
- Fix: Darken the two text colors a few percent; backgrounds and palette identity stay intact.
- Suggested command: /impeccable audit

**[P1] ƒ-stop radios have no visible focus indicator and no accessible name**
- Why it matters: Confirmed `outline:none` on focus and no label/aria-label — the core task-completing control is unusable via keyboard/screen reader.
- Fix: Wrap each radio in a real `<label>` (or aria-label="ƒ/1.4"); add a visible :focus-visible style.
- Suggested command: /impeccable audit

**[P1] The calculator's control row has no mobile breakpoint, unlike the Cameras page**
- Why it matters: Confirmed independently by both assessments (live measurement + CSS reading) — the one page without the mobile treatment its sibling page already has, despite the primary audience shooting in the field on a phone.
- Fix: Apply the same stacking rule used for .camera-control to #top-fields .column.
- Suggested command: /impeccable adapt

## Persona Red Flags

**Jordan (Confused First-Timer)**: Lands on a fully-populated grid with no indicator it's an example, not their result. Clearing the camera "to see what happens" hits the all-red "Infinity" table with no explanation.

**Sam (Accessibility-Dependent)**: Core task broken for keyboard/screen-reader use (no focus ring, no accessible name on radios). "maybe"/"bad" ratings fail 4.5:1 even before dimming.

**Field IR/UV Photographer (project-specific)**: Depends on the one control row with no confirmed mobile stacking; also most likely to reopen an old bookmarked link, making them most exposed to the silent invalid-camera failure with the least patience to debug it in the field.

## Minor Observations

- Default camera/filter shown on load is hardcoded in main.js; renaming that camera in cameras.yaml would silently break the zero-input default.
- #pitch-label styled gray vs. bold black on the other two labels — likely unintentional inconsistency on the field driving every calculation.
- /thirds/ omits the "How To Use" instructions block present on index.md.
- Masthead nav overlap: "Diffraction" home link visually overlaps the site title on every page (confirmed via bounding rects).
- Table header cells already carry ids that look built for scope/headers wiring but aren't connected yet.
- Detector's missing parser dependencies mean future audit/critique runs on this project should note the same degraded-mode caveat until those packages are available.

## Questions to Consider

- If the tool's value is "read the color at a glance," and that value provably disappears (~1.3:1) the moment someone picks a filter, is 25%-opacity dimming serving the product or just the CSS path of least resistance?
- PRODUCT.md commits to shareable, bookmarkable results, but both ways a shared link can fail do so silently — is "fast single-page result" quietly being prioritized over "a result that survives being shared"?
- An instrument that reads "Infinity" across every cell, in red, the moment an input is missing — trustworthy field gear, or broken gear?
